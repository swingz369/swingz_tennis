## 2. 🎫 API Endpoint Mismatches (offen)

### 2.1 `/api/auth/forgot-password` existiert nicht

**Befund:** Die `app/forgot-password/page.tsx` (neu erstellt) ruft `apiFetch('/api/auth/forgot-password', { method: 'POST', body: { email } })` auf. Der Endpoint existiert nicht.

**Impact:** Die Page rendert korrekt, das Form-Submit liefert aber 404 → User sieht Fehler-Toast "Anfrage fehlgeschlagen".

**Datei-Liste** (`app/api/`):

```bash
$ find app/api -name 'route.ts' -path '*forgot*' 2>/dev/null
# (leer)
$ grep -rn 'forgot-password\|reset-password' app/api 2>/dev/null
# (leer)
```

**Fix-Skizze:**

```typescript
// app/api/auth/forgot-password/route.ts
export async function POST(request: NextRequest) {
  return withApiAuth(request, async (auth) => {
    const { email } = await request.json();
    if (!email) return NextResponse.json({ error: 'email required' }, { status: 400 });

    // Always return 200 to avoid email enumeration
    await sendPasswordResetEmail(email);

    return NextResponse.json({ success: true });
  });
}
```

Zusätzlich wird `sendPasswordResetEmail()` benötigt (entweder via Resend, Supabase Auth, oder custom SMTP).

## 3. 🎫 Type-Inkonsistenzen (offen)

### 3.1 `TrainerProfile`-Type in `components/trainer-profile-management.tsx` fehlen neue Felder

**Befund:** Die Migration `20260610_add_trainer_dual_rate.sql` und der Drizzle-Schema in `src/infrastructure/persistence/schema.ts` haben `contracted_hourly_rate` + `extra_hours_rate` ergänzt. Auch die generierten Supabase-Types (`supabase-types.ts` + `types/supabase.ts`) wurden via Python-Script aktualisiert. **Aber:** Die manuelle `TrainerProfile`-Interface in `components/trainer-profile-management.tsx` (welche von `trainer-detail-client.tsx` importiert wird) hat diese Felder **nicht**.

**Impact:** Das Code-Rendering funktioniert aktuell, weil die Detail-Page die Felder nicht anzeigt. Sobald Sub-Task 3a/3b (UI-Wiring) umgesetzt wird, gibt es Type-Errors.

**Beweis:**

```bash
$ grep -n 'contracted_hourly_rate\|extra_hours_rate' \
    components/trainer-profile-management.tsx
# (leer)
```

**Im Gegensatz dazu hat `app/(protected)/admin/trainers/trainer.types.ts` (für die List-Page) die Felder bereits:**

```typescript
contracted_hourly_rate: number | null;
extra_hours_rate: number | null;
```

**Fix:** Felder zur `TrainerProfile`-Interface hinzufügen.

### 3.2 API-Handler kennt die neuen Felder nicht

**Befund:** `app/api/trainer-profiles/[id]/route.ts` (PATCH-Handler) destructuriert die existierenden Felder, aber nicht `contracted_hourly_rate` / `extra_hours_rate`. Auch `TrainerProfileService.updateTrainerProfile` (in `src/application/services/trainer-profile-service.adapter.ts`) kennt sie nicht.

**Impact:** Selbst wenn das Frontend die Felder sendet, werden sie vom Backend verworfen.

**Fix:** Beide Layer ergänzen, plus Role-Check im PATCH (Admin-only für `contracted_hourly_rate`).
