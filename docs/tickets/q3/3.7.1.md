## ⚠️ Ausführungshinweis (Pflicht)

**`npx supabase db push` MUSS manuell auf einer Entwickler-Maschine ausgeführt werden —
NICHT aus der Codebuff-Sandbox heraus.** Die Sandbox hat keine ausgehende Verbindung zum
Supabase-Projekt `qeckztuzeymuwwtyoryi` (Pooler-Host), und ein versehentlich gestarteter
`db push` aus der Sandbox könnte den Migrations-Tracker beschädigen.

Konkreter Ablauf:

```bash
# 1. Auf dev-Maschine klonen, branch ausschecken:
git clone git@github.com:aeugeln/SwingZ.git
cd SwingZ
git checkout -b chore/apply-20260627-elo-batch

# 2. (siehe "Geänderte / neue Dateien" unten — neue Migrationen anlegen)
#    Elo-Migration aus orphaned commit wiederherstellen
git show 9220e43749d893fc673b5859770e6084991a0bbe:supabase/migrations/20260627_elo_rating_system.sql \
  > supabase/migrations/20260627_elo_rating_system.sql

# 3. supabaseStack lokal starten
npx supabase start

# 4. Lokal prüfen, dass die Migrationen trocken durchlaufen
npx supabase db reset --no-seed    # frischt lokale DB komplett auf; alle 20260627_* in lex-order

# 5. Auf remote anwenden
npx supabase link --project-ref qeckztuzeymuwwtyoryi
npx supabase db push

# 6. Akzeptanz-Test
bash scripts/smoke-test-20260627-prod-activation.sh
# Erwartet: exit-code 0, JSON payload "overall":"PASS","pass":4,"fail":0
```

## Apply-Order (lexikografisch sortiert ist Pflicht)

Supabase `db push` sortiert Migrations-Files alphabetisch. Daher MUSS die Datei für die
`matches`-Tabelle lexikografisch VOR `20260627_elo_rating_system.sql` stehen:

| Reihenfolge | Datei | Wirkung |
|---|---|---|
| 1 | `20260627_create_matches_table.sql` (NEU) | erstellt `public.matches` + RLS + Indizes |
| 2 | `20260627_elo_rating_system.sql` (RECOVERED) | fügt `users.elo_rating`, `elo_history`, `compute_elo_delta`, `trg_match_elo_update` |
| 3 | `20260627_season_group_weeks.sql` (EXISTING) | erstellt `season_group_weeks` |

**Warum `matches` zwingend zuerst?** Die recoverable ELO-Migration (siehe
`/tmp/elo_migration_recovered.sql`, Zeile 91 `REFERENCES public.matches(id)` und Trigger
`AFTER INSERT OR UPDATE ON public.matches`) referenziert die Tabelle, ohne sie zu erzeugen.
Ein direkter Apply ohne vorherige `matches`-Tabelle würde mit Fehler
`relation "public.matches" does not exist` abbrechen.

### ⚠️ Skelett für `20260627_create_matches_table.sql` — DO NOT APPLY AS-IS

> **WARNUNG**: Das untenstehende Skelett ist eine **Orientierung**, kein
> produktionsreifer Code. Vor dem Authoring MUSS der Spalten-Shape gegen
> `/tmp/elo_migration_recovered.sql` Zeilen 6–150 exakt abgeglichen werden:
>
> - `compute_elo_delta(input1 elo_rating, input2 elo_rating, score1 int, score2 int)`
>   erwartet pro Seite eine Score-Summe und nutzt Per-Side-Average über
>   `side_left`/`side_right` (Doubles → Tournament-Modus).
> - FK-Constraints in `elo_history` (z. B. `match_id uuid NOT NULL REFERENCES
>   public.matches(id) ON DELETE CASCADE`) müssen zu Spalten in dieser Tabelle passen.
> - RLS-Policies dieser Tabelle müssen mit Trainer-/Admin-Rollen
>   konsistent sein (siehe `2.2.1` für RBAC-Pattern).
>
> **Reviewer-Gate**: Vor `npx supabase db push` MUSS ein zweiter Maintainer
> das ausformulierte SQL gegen `/tmp/elo_migration_recovered.sql` abgenommen haben.

```sql
-- 20260627_create_matches_table.sql
-- Schema der Matches-Tabelle, auf die 20260627_elo_rating_system.sql
-- via FK + Trigger referenziert. Felder incl. RLS werden mit der
-- bestehenden match_results-Tabelle abgeglichen.

CREATE TABLE IF NOT EXISTS public.matches (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  club_id       uuid NOT NULL REFERENCES public.clubs(id) ON DELETE CASCADE,
  group_id      uuid NOT NULL REFERENCES public.groups(id) ON DELETE CASCADE,
  created_at    timestamptz NOT NULL DEFAULT now(),
  played_at     timestamptz NOT NULL,
  side_left     jsonb NOT NULL,                  -- {player_ids: [...], score: int}
  side_right    jsonb NOT NULL,
  winner_side   text CHECK (winner_side IN ('left','right','draw')) NOT NULL,
  is_official   boolean NOT NULL DEFAULT false,   -- nur OFFICIAL matches triggern ELO
  updated_at    timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_matches_club_id      ON public.matches(club_id);
CREATE INDEX IF NOT EXISTS idx_matches_played_at    ON public.matches(played_at);
CREATE INDEX IF NOT EXISTS idx_matches_is_official  ON public.matches(is_official)
  WHERE is_official = true;

ALTER TABLE public.matches ENABLE ROW LEVEL SECURITY;
-- Club-Mitglieder dürfen lesen; Trainer/Admins dürfen schreiben
-- (exakte Policies mit Billing-/Trainer-RBAC synchronisieren — Details TODO in 3.7.1)
```
