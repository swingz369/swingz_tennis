## Ziel

Bei Drift → **PR-FAIL** + Kommentar-Annotation mit Diff-Summary; bei Konsistenz → ✅ grün.

**Verhindert die Wiederholung des FK-Drift-Bugs vom 2026-05-07** (`Commit fdd1ce0`, Verursacher: `swingz369`, Message „fix: eliminate all 149 TypeScript errors"). Damals driftete der Drizzle-Snapshot-Cache leise von der Live-DB ab; der Cluster-Engine-bug 23503 auf `season_plan_entries.group_id` wurde durch Tests nicht gefangen, weil Mocks keine FK-Violations reproduzieren. Ein CI-Gate, der den generierten Snapshot vor PR-Merge mit der Live-DB-Staging vergleicht, hätte den Drift **vor PR-Merge** sichtbar gemacht.

## Workflow-Spec (Detail)

```yaml
# .github/workflows/drizzle-drift-check.yml
name: Drizzle Live-Snapshot Drift Check
on:
  pull_request:
    types: [opened, synchronize, reopened, edited]
    paths:
      - 'drizzle/**'
      - 'src/infrastructure/persistence/schema.ts'
      - 'supabase/migrations/**'
permissions:
  contents: read
  pull-requests: write    # für Drift-Annotations
  id-token: none
jobs:
  drift-check:
    runs-on: ubuntu-latest
    timeout-minutes: 6
    env:
      SUPABASE_STAGING_DB_URL: ${{ secrets.SUPABASE_STAGING_DB_URL }}
      SUPABASE_STAGING_SERVICE_ROLE_KEY: ${{ secrets.SUPABASE_STAGING_SERVICE_ROLE_KEY }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - name: Generate Drizzle snapshot from current schema
        run: pnpm drizzle-kit generate --name=ci-snapshot
      - name: Push dry-run against staging (read-only diff)
        # PSL: 'chrome' = Drizzle-Kit confirms kein Drift -> exit 0
        #      'modified' = Drift vorhanden            -> exit non-zero
        run: pnpm drizzle-kit push --dry-run --verbose
      - name: Annotate PR on drift
        if: failure()
        uses: marocchino/sticky-pull-request-comment@v2
        with:
          header: drizzle-drift
          message: |
            ⚠️ **Drizzle SQL-Snapshot driftet vom Live-Supabase-Staging**
            Ein DDL-Diff wurde erkannt. Bitte vor Merge manuell prüfen.
            See: docs/tickets/q3/3.7.5.md
      - name: Cleanup CI snapshot
        if: always()
        run: rm -rf drizzle/ci-snapshot drizzle/meta/_journal.json.bak
```

### Erwartete Outputs

- **Clean PR** (Snapshot === Live): Workflow grün, kein Drift-Annotation.
- **Drift PR**: Workflow failt, Annotation erscheint als `<!-- drizzle-drift -->`-Comment auf dem PR (sticky = bleibt bei Re-Runs oben).

### Warum `push --dry-run`?

- `drizzle-kit generate` erzeugt nur die Snapshot-Datei — kein DB-Round-Trip.
- `drizzle-kit push --dry-run` baut die SQL-Migration auf und fragt die **Ziel-DB** (Staging) in einer Transaktion, ohne zu committen. Drift = echtes `pg_diff`-Ergebnis, nicht „Snapshot-Hash-Vergleich" (das nur File-Drift fängt).

Alternative: `drizzle-kit check` (statischer Compare der Snapshot-JSONs). Findet nur Drift zwischen lokalen Snapshot-Dateien und Alt-Snapshots, NICHT gegen Live-DB. Daher **nicht** ausreichend.

## Vorteile / Risiken (Consequences)

Pro:
- Verhindert die exakte Bug-Klasse des FK-Drifts nach 3.7.4 / 3.7.5 für alle zukünftigen Schema-Änderungen.
- Ergänzt die existierende CI (tsc, vitest, e2e) um einen **DDL-Layer**.
- Annotation direkt auf PR = schnelles PR-Reviewer-Feedback, kein „erst beim Apply auf dev-Maschine gemerkt".

Contra:
- Staging-DB muss gepflegt sein — sonst „always green" (= false negative).
- Service-Role-Key im CI-Secret ist sicherheitskritisch — muss rotiert werden.
- Performance: `drizzle-kit push --dry-run` braucht ca. 30-60 s pro Lauf, verlängert die CI-Pipeline.
- Bei massiven Schema-Drifts (z.B. nach umfangreichen PRs) wird die Annotation sehr lang — ggf. Kürzung erforderlich.
