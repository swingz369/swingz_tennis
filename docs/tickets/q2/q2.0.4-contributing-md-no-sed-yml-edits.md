# Q2.0.4 — CONTRIBUTING.md: Rule 1.1 für YAML/JSON Config-Files

## Kontext

CONTRIBUTING.md Rule 1 verbietet `sed -i` auf `.ts`-Files (Sprint-4-Lesson).
Der gleiche Risk existiert für:

- `.github/workflows/*.yml` — GitHub-CI-Workflows (nested-key YAML-Semantik)
- `vercel.json` — Hosting-Config (JSON, schema-aware)
- `.lighthouserc.json` — Lighthouse-CI-Config
- `package.json` — Schema-aware JSON (npm understands the schema)

**Beispiel-Risk:**

```bash
# Was in Sprint-4 mit .ts schief ging:
sed -i 's/.../(/(_table) => [/};,' drizzle/schema.ts
# Was gleich für YAML passieren könnte (zukünftige Lessons):
sed -i 's/timeout: 15/timeout: 30/' .github/workflows/bundle-analyzer.yml
# ⚠️  Gefahr: trifft alle 'timeout: 15' Vorkommen, auch in jobs die nicht
#     bundle-analyzer sind. Workflow bricht CI für andere Jobs.
```

## Ziel

CONTRIBUTING.md Rule 1 erweitern (oder neue Rule 1.1 hinzufügen) mit:

1. **No-sed-Liste** auf YAML + JSON ausdehnen
2. **File-Pattern-Tabelle** (analog `.ts` Row in Rule 1):
   - YAML → `yaml.safe_load + safe_dump` round-trip via Python
   - JSON → `jq` oder Python `json.tool`
   - package.json → `npm pkg set` (schema-aware)
3. **Recovery-Pattern** analog zu Rule 1 (concrete shell snippet)

## Akzeptanzkriterien

- [ ] **CONTRIBUTING.md Rule 1 um eine Sub-Section `1.1` ergänzt:**
      ```markdown
    ### 🔴 Rule 1.1: No `sed -i` on configuration files (.yml, .yaml, .json)

      Same reasoning as Rule 1, but for **CI/Tool configuration files**:

      | File Pattern | Safe tool | Why |
      |---|---|---|
      | `.github/workflows/*.yml` | `write_file` (recreate workflow) | YAML has nested-key semantics — sed can't reason about indentation |
      | `vercel.json` | `jq` (round-trip JSON) | Preserves key-ordering + applies jq syntax |
      | `.lighthouserc.json` | `jq` or Python `json` | Same as vercel.json |
      | `package.json` | `npm pkg set <key>=<value>` | Schema-aware editor |

      **Recovery example** (sed disaster on YAML):
      ```bash
      # 1. Confirm damage: how many new errors?
      yamllint .github/workflows/*.yml 2>&1 || true

      # 2. Restore from git
      git checkout HEAD -- .github/workflows/

      # 3. Re-apply the original intent via Python with structure-aware round-trip
      python3 <<'PYEOF'
      import yaml
      for f in ['.github/workflows/bundle-analyzer.yml']:
        with open(f) as fh: doc = yaml.safe_load(fh)
        # Apply semantic edits here, e.g.:
        # doc['jobs']['analyze']['steps'][0]['with']['output-name'] = 'optimized-build'
        with open(f, 'w') as fh: yaml.safe_dump(doc, fh, default_flow_style=False)
      PYEOF
      ```
