# Q2.0.2 — `ALLOWED_BRANDING_KEYS` aus `clubs.$inferInsert` ableiten

## Kontext

In `app/api/branding/route.ts` L120-128 (nach Sprint-4-Fix) ist
`ALLOWED_BRANDING_KEYS` als hardcoded Set<String> mit 8 String-Literalen
definiert:

```ts
const ALLOWED_BRANDING_KEYS: Set<string> = new Set([
  'primary_color',
  'secondary_color',
  'accent_color',
  'logo_light_url',
  'logo_dark_url',
  'favicon_url',
  'custom_domain',
  'updated_at',
]);
```

Vorteile der Hardcoded-Liste:

- Explizit: welche Spalten sind "branding-relevant" (= typos explizit sichtbar)
- Audit-freundlich: Security-Reviewer kann die Liste direkt prüfen

Nachteile der Hardcoded-Liste:

- Schema-evolve-fragile: jede neue `clubs`-Spalte für Branding erfordert
  explizites Update hier
- Sprint-4-Bug war genau diese Lücke: code schrieb `primary_color` aber
  Allowlist hatte es nicht → 400-Responses in Produktion

## Ziel

Hardcoded-Liste durch **Typ-sichere Ableitung** aus `clubs.$inferInsert`
ersetzen (oder als Wide-Type mit explizitem Curated-Set):

```ts
// Option A — Wide-Type (alle writable columns erlaubt):
type ClubsUpdate = Database['public']['Tables']['clubs']['Update'];
const ALLOWED_BRANDING_KEYS = new Set<keyof ClubsUpdate>([
  'primary_color',
  'secondary_color',
  'accent_color',
  'logo_light_url',
  'logo_dark_url',
  'favicon_url',
  'custom_domain',
  'updated_at',
]);

// Option B — Object.keys-Derivation (vollautomatisch):
const ALLOWED_BRANDING_KEYS: Set<keyof ClubsUpdate> = new Set(
  Object.keys({} as ClubsUpdate) as Array<keyof ClubsUpdate>
);
// ⚠️  Allowlist = ALLE writable columns (auch sensitive Spalten!)
```

**Empfehlung: Option A** — Wide-typed curatierte Liste. Beibehält
Audit-Freundlichkeit (explizite Liste) + Schema-evolve-Resilienz (TypeScript
erkennt Tippfehler bei Compile-Time, nicht Runtime).

## Akzeptanzkriterien

- [ ] Hardcoded-Liste ersetzt durch `Set<keyof ClubsUpdate>`-typed Set.
- [ ] Import von `Database` aus `types/supabase.ts` (Source-of-Truth-Schema-Type).
- [ ] Vitest `tests/unit/api/branding.test.ts`:
  - [ ] Test: PUT mit jedem der 8 branding-keys + jedem anderen writable
        clubs-key (z. B. `name`, `slug`, `max_members`) — `name`/`slug`/
        `max_members` sollten von Allowlist rejected werden (weil nicht in
        branding-list).
  - [ ] Regression-Guard: jeder neue writable clubs-key MUSS explizit zur
        Branding-Liste hinzugefügt werden, sonst Compile-Error.
- [ ] Tsc-baseline bleibt 0 Produktionsfehler.
- [ ] ADR-008 erstellt mit explizitem **Begründungs-Bullet** für Curated-Set
      (statt Auto-Derivation aus Sicherheits-Gründen — würde sensible
      Spalten wie `billing_unit_minutes` oder `default_payment_method`
      versehentlich erlauben).

## Out-of-Scope

- `color`-Spalten-Sanity-Validierung (Regex `^#[0-9A-Fa-f]{6}$` ist bereits
  in `BrandingUpdateSchema` Zod gecheckt).
- Multi-Tenant-Branding-Isolation (separate Branding-Tabelle pro Club).
- Hot-Reload der Allowlist (kein Use-Case).

## Trade-Off-Diskussion

| Aspekt                          | Option A (curatierte Wide-Type)                 | Option B (Auto-Derivation)                                         |
| ------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------ |
| Compile-Time-Safety             | ✓ (TS akzeptiert nur echte Spalten)             | ✓                                                                  |
| Schema-evolve-Resilienz         | bedingt (TS zeigt Compile-Error bei Tippfehler) | ✓ (auto)                                                           |
| Audit-Freundlichkeit            | ✓ (explizite Liste im Code)                     | ✗ (Liste = alle writable Spalten)                                  |
| Risk: sensitive Spalten erlaubt | ✓ (curated ausschließen)                        | ✗ (`billing_unit_minutes`, `default_payment_method`, etc. erlaubt) |

Empfehlung: **Option A** (Default). Sicherheit > Auto-Aktualisierung.

## Migration-Sketch

```ts
// app/api/branding/route.ts ~ L20-25
import type { Database } from '@/types/supabase';
type ClubsUpdate = Database['public']['Tables']['clubs']['Update'];

// L120-128
const ALLOWED_BRANDING_KEYS: Set<keyof ClubsUpdate> = new Set([
  'primary_color',
  'secondary_color',
  'accent_color',
  'logo_light_url',
  'logo_dark_url',
  'favicon_url',
  'custom_domain',
  'updated_at',
  // Neue branding-relevante Spalten hier ergänzen.
]);

for (const k of Object.keys(updates)) {
  if (!ALLOWED_BRANDING_KEYS.has(k as keyof ClubsUpdate)) {
    return NextResponse.json({ error: `Unknown branding field: ${k}` }, { status: 400 });
  }
}
```
