# Q2.0.0 — Merge `member_schedule_preferences` + `user_training_preferences` schemas

## Origin

The cast `as unknown as MergedPrefRow[]` in `lib/season-planning/clustering-engine.ts`
loadMembers() merge-step is documented as a "known TS escape hatch for matches-at-runtime-but-TS-can't-see-it".
It exists because the two source tables have **structurally different row types**:

| Table                               | Row type                     | `wish_partner_ids` | `weekly_availability` |
| ----------------------------------- | ---------------------------- | ------------------ | --------------------- |
| `user_training_preferences` (utp)   | per-season wizard submission | `string[] \| null` | `WeeklyAvailability`  |
| `member_schedule_preferences` (msp) | per-club baseline form       | `Json \| null`     | `Json`                |

Both tables serve semantically-equivalent "user's scheduling preferences" — but the
upstream SQL DDL has them split, with Drizzle types diverging accordingly.
The merge-step in `loadMembers()` then has to bridge these at the application layer
with `as unknown as`. **This is a band-aid, not a fix.**

## Goal

Unify the two `*_preferences` tables at the DB schema level so the cast in
`clustering-engine.ts` disappears entirely. Target end state:

```ts
// BEFORE (Sprint-4 state):
const mergedRows: MergedPrefRow[] = [
  ...seasonPrefs,
  ...(eligibleBaseline.map((bp) => ({...})) as unknown as MergedPrefRow[]),  // BAD
];

// AFTER (Q2.0.0 target):
const mergedRows: MergedPrefRow[] = [
  ...seasonPrefs,
  ...eligibleBaseline.map((bp) => ({...})),  // No cast needed!
];
```

## Acceptance Criteria

1. **Schema migration** `supabase/migrations/<YYYYMMDD>_merge_preferences_tables.sql`:
   - Choose ONE of two strategies (keep `utp` + `msp` views backed by a single table, OR migrate legacy `msp` rows into `utp` and drop `msp`).
   - Document preference for "consolidate to utp" — it has richer column set + DB CHECK constraints + per-season scoping.
   - RLS policies apply uniformly to the consolidated table.
   - Backward-compat: any existing reader/writer using `member_schedule_preferences` keeps working via a Postgres view OR via Drizzle aliasing.
2. **Source-of-truth update**: `src/infrastructure/persistence/schema.ts` — single `userPreferences` pgTable definition (or alias) shared by both column-sets.
3. **Type cleanup**: `app/api/user/member/route.ts`, `app/api/members/*`, `app/(protected)/member/preferences/*`, and `clustering-engine.ts` ONLY need to import the unified type — no JSON-cast branches, no `as string[]` defensive coercions.
4. **Removal of cast at L498**: `lib/season-planning/clustering-engine.ts` — the explicit `as unknown as MergedPrefRow[]` cast is gone. `MergedPrefRow['pref']` retains its full strict typing (the 3 utp-only fields stop being optional because both branches now have them).
5. **Vitest regressions**: All existing tests in `tests/unit/lib/season-planning/*` and `tests/unit/components/member-profile/*` pass without modification (no test should need a fix because of this).
6. **tsc-baseline**: 0 production errors after removal of cast (was 1 with the cast workaround; should be 0 with the proper schema fix).

## Out of Scope

- Performance optimization of the merge step (covered by Sprint-4 P0 #1 slot-cache; cached separately).
- New features for either wizard (per-season) or baseline form (per-club). This ticket only merges the storage so the type system + linear code paths stop branching.

## Trade-offs Considered

| Option                                                       | Pros                                                                 | Cons                                                                           |
| ------------------------------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **A. Migrate msp rows into utp, drop msp**                   | Single source of truth; no view overhead; cleanest type unification  | One-time data migration; existing `msp` selectors break unless alias-rewritten |
| **B. Add utp-shape columns to msp, keep both tables**        | No data migration; backward-compat via SELECT FROM                   | Two tables still exist; type unification still requires union                  |
| **C. Postgres view over a unified `user_preferences` table** | Backward-compat at the SELECT layer; both API paths keep their table | Drizzle types need shimming; 1 indirection in queries                          |

**Recommendation: Option A** — the legacy `msp` table was always a stopgap until per-season
preferences became the canonical source. The clustering engine already prefers `utp`
when present and falls back to `msp` only as a safety net — once they're unified,
the fallback path disappears.

## Implementation Sketch (Option A)

```sql
-- 1. Add utp-shape columns to ms (or vice-versa) — see schema survey in codebase.
-- 2. Data migration: INSERT INTO user_training_preferences SELECT ... FROM member_schedule_preferences
--    WHERE NOT EXISTS (matching season + user_id).
-- 3. DROP member_schedule_preferences.
-- 4. Update FK references (none expected — column-set is small).
-- 5. Verify RLS policies transferred intact.
```

```ts
// schema.ts (after):
export const memberPreferences = pgTable('member_preferences', {
  // Single consolidation of msp + utp columns
  id: uuid('id').defaultRandom().primaryKey(),
  user_id: uuid('user_id')
    .notNull()
    .references(() => users.id),
  club_id: uuid('club_id')
    .notNull()
    .references(() => clubs.id),
  season_id: uuid('season_id').references(() => seasons.id), // NULL for club-baseline rows
  weekly_availability: jsonb('weekly_availability').$type<WeeklyAvailability>().notNull(),
  preferred_court_ids: jsonb('preferred_court_ids').$type<string[]>().default([]),
  preferred_trainer_ids: jsonb('preferred_trainer_ids').$type<string[]>().default([]),
  preferred_age_group: text('preferred_age_group'),
  preferred_level: text('preferred_level'),
  max_sessions_per_week: integer('max_sessions_per_week'),
  unavailable_dates: jsonb('unavailable_dates').$type<string[]>().default([]), // utp-only, but typed
  avoid_member_ids: jsonb('avoid_member_ids').$type<string[]>().default([]), // utp-only
  self_assessed_level: text('self_assessed_level'), // utp-only
  wish_partner_ids: jsonb('wish_partner_ids').$type<string[]>().default([]),
  is_submitted: boolean('is_submitted').default(false), // utp-only
  user_role: text('user_role'), // utp-only
  // ... rest of utp columns
});
```
